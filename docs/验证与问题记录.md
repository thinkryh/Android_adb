## 已试方法、失败结果与当前处理

| 问题／现象 | 已尝试或查明 | 结果与当前处理 |
| --- | --- | --- |
| 早期 BAT 中文排版错乱，输出英文“not recognized”、路径找不到 | 调整中文输出、编码与批处理换行；仓库规定 `*.bat` 为 CRLF | 早期 LF／编码组合会让 CMD 误解析。当前根 BAT 为 CRLF，若再次出现先检查文件换行和是否被单独复制 |
| 他人电脑提示 PowerShell 禁止执行脚本 | 根 BAT 以 `-ExecutionPolicy Bypass -File` 调用 v1 脚本 | 这是旧版 v1 的启动问题；v2 有发布程序时直接启动 EXE，不经过 PowerShell。目标电脑还需对应 .NET Runtime |
| 无线配对成功但后续失败、要求反复输入地址 | 区分临时配对端口与无线调试主页面连接端口，并记录成功使用的连接地址 | v1 已由用户确认可用；v2 只在设备列表为空时重连至多 4 个记录地址。地址可能因网络变化失效，仍需用户重新确认 |
| 无线明显卡顿，误把已连接无线设备当作有线 | 修正设备类型判定，固定无线均衡参数，不再要求启动时反复选画质 | 目前按 ADB 序列号类型区分 USB／无线，真实弱网和同一手机双通道仍需专项验证 |
| 投屏窗口标题空白 | 设置 scrcpy `--window-title` 为“Android投屏助手 - 设备名” | 当前代码保留此参数；不同 scrcpy 版本需在真机窗口上复核 |
| 工具栏与投屏窗口有间隙、拖动主窗不跟随、层级穿插 | 改为可见窗口边界计算吸附位置，添加系统窗口事件跟随，并将快捷栏设为投屏窗口 owned window | 代码路径已建立，吸附时提供边框反馈与滑入动画；复杂桌面／多显示器仍是待验收项 |
| 快捷栏功能过多或按钮不齐；暗色外框和录屏按钮太亮 | 移除息屏、全屏、音量等按钮；重做等宽矢量图标、暗色边框、录屏色和收起入口 | 当前保留置顶、主页、返回、最近任务、截图、录屏。需要按 100%／125%／150% 缩放目测复核 |
| 录屏报 `Time limit 360s outside acceptable range [1,180]` | 把单段上限改为 180 秒；停止时向 Android `screenrecord` 发送 SIGINT，等封装后再 `adb pull` | 360 秒方案失败，已取消。仅文件存在或弹出“成功”不足以证明可用，现检查 MP4 的 `ftyp`／`moov` |
| 电脑端录屏首次沙箱验证失败 | ScreenRecorderLib 报 Windows Graphics Capture 不可用；在正常桌面会话重试可录制，但静态窗口视频仅 840 字节 | 旧的 1024 字节最小值误判合法短视频；改为检查 `ftyp`、有内容的 `mdat` 和 `moov`，动态窗口复测得到 11,533 字节 MP4 |
| 曾提示录屏成功但电脑找不到文件 | 改为在本机“图片\Android投屏助手”中创建文件，拉取后检查非空及 MP4 完整索引；失败保留手机原件 | 正常路径已做实测；网络／USB 中断时仍可能需要从手机 `/sdcard/` 手动恢复 |
| 截图保存需等待约 1–2 秒 | 试过 ADB 原画抓取，后加入 Windows `PrintWindow` 快速截取投屏窗口 | 左键优先快速截当前窗口、失败回退原画；右键直接取原画。快速图像分辨率较低是此方案的明确取舍 |
| 自动化 `ShutdownSmoke.exe` 曾弹未知软件异常 | 对测试程序与正式投屏助手的进程边界做过排查 | 不能把测试程序异常归因于正式应用，也不能当成正式应用已通过退出稳定性测试；退出／录屏并发仍需单独复测 |
| 沙箱中 ADB 提示 `Cannot mkdir '\\.android': Permission denied` | 核对该错误发生在受限测试环境，而非手机反馈 | 此失败不能证明真机无法投屏；应在有权限的实际 Windows 会话复核 |
| 试图通过 Windows Computer Use 操作已打开的应用，但返回 `apps: []` | 核对应用可运行、进程路径及窗口可见；重复枚举仍为空 | 属于自动化环境无法绑定窗口，不能据此声称实际界面点击已验证，也不应继续改投屏程序掩盖工具限制 |

## 尚未完成的验收

1. Android 11+ 多机型下的配对码与 IP 直连全流程；配对成功后连接、重启后复用、端口变化及失败回退分别验证。
2. 两台以上手机同时投屏；一台手机 USB 与 Wi-Fi 同时在线时的去重和优先级规则。当前按序列号管理，物理设备去重尚未实现。
3. 快捷栏在投屏窗口拖动、最小化／恢复、被其他窗口覆盖、跨显示器、混合 DPI 下的贴合与层级；收起状态同样覆盖这些场景。
4. 真实 scrcpy 窗口的电脑端录屏与计时 UI、投屏窗口意外关闭、最小化、不同显卡及 VC++ 运行库环境；现在不再使用手机端 `screenrecord`，也没有 180 秒上限。
5. 截图在投屏窗口被遮挡、最小化和不同显卡驱动下的内容正确性；快速模式不能只检查 PNG 文件非空，还要人工确认不是黑屏或旧帧。
6. 目标电脑没有 .NET 10 Desktop Runtime、缺少依赖 DLL、路径含空格或中文，以及解压／重新分发的端到端安装体验。

复核时优先保留可观测证据：实际启动程序路径、ADB 设备状态、scrcpy 进程 ID、目标 PNG／MP4 的路径与大小、截图内容／视频可播放性、失败提示和 Android 版本。公开分享证据时先将私有 IP、端口、配对码与设备序列号脱敏。

本轮代码审查还确认：同一部手机同时经 USB 和 Wi-Fi 连接时，当前仍按不同 ADB 序列号显示为两张卡片，未做物理设备去重。
